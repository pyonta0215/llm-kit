# ADR 0001: research-kit を llm-kit に改名し、モデル名と単価の目録を持つ

- Status: Accepted
- Date: 2026-11-03

## 背景

このキットを使う側のプロダクトが、モデル名と単価をそれぞれ書き写していた。モデルの更新のたびに複数のリポジトリを直す必要があり、それでも食い違いが残っていた。公式の料金ページと照らすと、キャッシュ済み入力の単価が設定されていない表や、キャッシュ書き込みの単価・長いコンテキストの割増が入っていない表があった。

同じ事実を複数の場所に書くと、どこかが古いまま残る。一方でこのキットの README は「単価表そのものは入れない（転記日と出典は利用側で管理する）」としていた。ライブラリに利用側固有の値を入れないためだったが、公開単価は利用側によらず同じ事実なので、この理由は単価には当たらない。

また、このキットの中身（応答の読み取り・JSON の取り出し・費用の計算・予算の予約と精算）は、調べもの専用ではなく、モデルの API を呼ぶときの共通処理になっていた。

## 決定

- リポジトリを GitHub の改名で research-kit から **llm-kit** に変える。パッケージ名は 0.3.0 から `@pyonta0215/llm-kit`
- `catalog` を足し、モデル名と単価の正本にする。各行に確かめた日（`checkedOn`）と出典（`source`）を持たせる
- 単価は Standard tier の公開単価を、出典のページから転記する。記憶では書かない
- 「単価表を入れない」の決まりは、この ADR で置き換える。プロンプト・業務スキーマ・予算の上限などの利用側固有の値は、これまでどおり入れない

## 採らなかった案

- **新しいリポジトリ llm-kit を作り、research-kit をアーカイブする**：同じコードが2か所になり、移行が終わるまで修正を両方に当てる。GitHub の改名は古い URL の git 操作を転送するので、新しいリポジトリにする理由がない（Actions も Pages も持っていない）
- **互換用に research-kit の名前で薄いリポジトリを残す**：古い名前を再利用すると、改名の転送が切れる
- **改名せず catalog だけ足す**：中身と名前が合わないまま、利用側が「調べもの用」の部品から単価を引くことになる
- **利用側に単価を持たせ続け、ずれを点検で見張る**：更新のたびに複数のリポジトリを直す手間が残る

## 結果

- 古いタグ（v0.1.0・v0.2.0）は書き換えない。既存の参照は改名の転送でそのまま動く
- **research-kit という名前のリポジトリは今後作らない**（作ると転送が切れる）
- 利用側は、版を上げるときに依存の名前と import を書き換える
- 単価が変わったら、この目録を1か所直してタグを切り、利用側の版を上げる
